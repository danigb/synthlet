FAUST 2.85.9.
vaeffects.lib 1.5.0, git blob 3aa5fe856b9dbea7c125d518666d764771cd54d1
  (unchanged upstream between faustlibraries ab116d8, 2026-03-11, and
  56729e3, 2026-08-26).

Check the library before regenerating:
  git hash-object "$(dirname "$(readlink -f "$(which faust)")")/../share/faust/vaeffects.lib"

`ve.moogLadder` and `ve.korg35LPF` in this package were once generated from
revisions with *incompatible* normFreq conventions and checked in side by
side, which is how a two-decade cutoff error survived three audits. Recording
the commands without the library version is what allowed it.

 faust -lang rust -cn Moog moog.dsp -o moog.rs
 faust -lang rust -cn MoogHalf moog-half.dsp -o moog-half.rs
 faust -lang rust -cn Korg35LPF korg35-lpf.dsp -o korg35-lpf.rs
 faust -lang rust -cn Korg35HPF korg35-hpf.dsp -o korg35-hpf.rs
 faust -lang rust -cn Oberheim oberheim.dsp -o oberheim.rs
 faust -lang rust -cn Diode diode.dsp -o diode.rs

The .ts files in ../src are hand transcriptions of these .rs files. Three
divergences are intended and must survive a regeneration:

  * `process()` takes `from`/`to` bounds so the worklet can render a block in
    runs of constant coefficients (see the 0.13.0 CHANGELOG).
  * oberheim.ts exposes one output selected by `type` rather than the four
    output buffers the Rust emits, with the tap mix hoisted out of the loop.
  * `fSlow0` is `prewarp(f)` from ../src/prewarp.ts, not `Math.tan(...)`.
    Two things collapse into that. First, `tan(2*PI/SR * 10^(3*normFreq(f)+1))`
    is `tan(PI*f/SR)` exactly, because normFreq is the inverse of the library's
    own map and the round trip is the identity - so the log and the power are
    two transcendental calls per coefficient update that undo each other, and
    on a per-sample sweep that is per sample. Second, the tangent has a pole at
    Nyquist, and `worklet.ts` folds +/-127 semitones of detune into the cutoff:
    `prewarp()` is Zavalishin eq. 3.23, which follows the tangent below 0.72 of
    Nyquist and continues it as a tangent line above. This is the largest
    divergence in the package. A regeneration must not silently undo it.
  * ../src/norm-freq.ts survives only as the *domain* of diode.ts's
    `17 - 9.7*normFreq^10` feedback term, which the library designs over 0..1
    and which is what returned `Infinity` past it.

Anything else is a bug. `input[0]` where the Rust reads `*input0` was one, and
it made four of the nine models filter a DC value re-latched once per block.
