`@synthlet/euclid`

Distribute `beats` hits as evenly as possible over `steps` steps and you get most
of the world's rhythms: `(3,8)` is the tresillo, `(5,8)` the cinquillo, `(5,16)`
the bossa-nova necklace. Sixteen of them ship with names.

It has no tempo of its own. Timing comes in on `clock` as a **phase ramp**, not a
gate — the step boundary is the ramp's wrap, which is what
[Clock](/docs/clock) puts on its main output. One pattern comes out on five
outputs at once:

```ts
import {
  registerAllWorklets,
  Clock,
  Euclid,
  KickDrum,
  TomDrum,
  CongaDrum,
  ClaveDrum,
} from "synthlet";

const ac = new AudioContext();
await registerAllWorklets(ac);

const clock = Clock(ac, { bpm: 60 });

// One pattern, four voices. `spread` is the only thing that differs between
// them: channel `i` plays the pattern at `rotation + i * spread`.
const rhythm = Euclid(ac, {
  clock,
  subdivision: 4,
  steps: 16,
  beats: 5,
  spread: 4,
});

const kick = KickDrum(ac, { trigger: rhythm }); // rotation 0 — E(5,16) as generated
const tom = TomDrum(ac, { trigger: rhythm.b }); // rotation 4
const conga = CongaDrum(ac, { trigger: rhythm.c }); // rotation 8
const clave = ClaveDrum(ac, { trigger: rhythm.d }); // rotation 12 — the bossa-nova

[kick, tom, conga, clave].forEach((drum) => drum.connect(ac.destination));

clock.bpm.value = 150;
```

The clave is playing `x..x..x..x..x...` — the bossa-nova, which is this necklace
at `rotation: 12` and is `EuclidRhythm.BossaNova`. The kick is the same five
onsets entered twelve steps earlier, which is not a rhythm anybody named. That
gap is the whole of [Named rhythms](#named-rhythms) below.

The drawing under the demo is `Euclid.pattern` on the same four rotations, one
row per voice. Turn **Rotation** and every row shifts one cell at a time — that
is what `rotation` is. Turn **Spread** to 0 and the four rows collapse onto one;
turn **Swing** and all four swing together, because they are one step phase.

## Named rhythms

<Callout title="rotation: 0 is not the named rhythm" type="warn">
  Of the 22 rhythms Toussaint publishes, 13 come out right at `rotation: 0` and
  9 do not — and no stated rotation rule reproduces more than 13. Reach for a
  preset, or look the rotation up; there is nothing to derive.
</Callout>

A necklace has no starting point, so where a tradition enters the cycle is
ethnomusicology and not arithmetic —
[Toussaint](https://archive.bridgesmathart.org/2005/bridges2005-47.pdf) §4 is
where the sixteen that ship were looked up. Each preset carries its own rotation,
and the pattern is a value you can read:

```ts
import { Euclid, EuclidRhythm } from "synthlet";

Euclid.pattern(8, 3); // [1,0,0,1,0,0,1,0] — the tresillo, and the default
Euclid.pattern(8, 5, 6); // [1,0,1,1,0,1,1,0] — the cinquillo
Euclid(ac, { clock, ...EuclidRhythm.Cinquillo }); // the same three numbers, named
```

`Euclid.pattern(steps, beats, rotation)` is the same expression the engine
rebuilds its pattern from, so it is what the node plays rather than a
reconstruction of it — and it needs no `AudioContext`, so it will draw you a ring
of LEDs. The demo above is doing exactly that.

The sixteen names, their rotations, their box notation and where each one comes
from are in the
[package README](https://github.com/danigb/synthlet/tree/main/packages/euclid#named-rhythms),
which is also where the played variants of each necklace live. They are one table
each and this page links them rather than keeping a second copy.

## Five outputs

The node plays the pattern's hits — channel a. `rhythm.rests` plays the steps
they leave empty, and `.b`, `.c` and `.d` play the same pattern entered further
in, `spread` steps at a time.

| Output          | What it is                                                                               |
| --------------- | ---------------------------------------------------------------------------------------- |
| the node itself | channel **a** — the pattern's hits, a pulse over the first `pulseWidth` of each hit step |
| `rhythm.rests`  | the steps channel a leaves empty — same width, same samples                              |
| `rhythm.b`      | the pattern at `rotation + spread`                                                       |
| `rhythm.c`      | the pattern at `rotation + 2 × spread`                                                   |
| `rhythm.d`      | the pattern at `rotation + 3 × spread`                                                   |

```ts
const rhythm = Euclid(ac, { clock, ...EuclidRhythm.Tresillo });
const kick = KickDrum(ac, { trigger: rhythm }); // x . . x . . x .
const hat = HiHatDrum(ac, { trigger: rhythm.rests }); // . x x . x x . x
```

The complement of a Euclidean rhythm is a Euclidean rhythm — Morrill's
[Lemma 3](https://arxiv.org/abs/2206.12421), _"Euclidean rhythms distribute
their rests in the same manner as their notes"_ — so `.rests` is
`E(steps - beats, steps)` at some rotation, not a leftover.

It is an output rather than a second node because that rotation is **never 0**.
Across all 2016 pairs with `1 ≤ beats < steps ≤ 64`, the complement of `E(k,n)`
is never `E(n−k,n)` as generated: `E(3,8)`'s rests are `E(5,8)` rotated by 5,
`E(5,16)`'s are `E(11,16)` rotated by 3. A second `Euclid` at
`beats: steps - beats` plays the right necklace from the wrong place, and there
is no rotation to work out by ear.

Every output comes off one pattern, one step counter, one `pulseWidth` and one
`reset`, read at the same sample — so the hits and the rests partition every
step, none of the five can skew, and one `reset` aligns all of them.
`steps: 0` is silence on every one. All five are
[gates](/docs/gates-and-triggers), like everything
[Clock](/docs/clock) emits on `.gate`.

The complement is **dense**, and that is the point: `E(3,8)`'s rests are five
hits in eight. Sparse kick, busy hat. It is not a second layer of the same
pattern — onsets move rather than accumulate.

`.rests` adds no parameters, and it is the complement of **channel a only** —
the complement commutes with rotation, so the complement of any other channel
is one patched node away at the rotation you want. The base complement is the
one no second node can reach, which is why that one is an output.

### The fan

One necklace is several named rhythms at once. On E(9,16): started on its
fourth onset it is played in West and Central Africa and is also the Brazilian
samba cowbell; on its penultimate onset it is the Ngbaka-Maibo bell pattern.
Those are the parts different players hold **simultaneously**, over one cycle.

`spread` is that, as one knob. Channel _i_ plays
`Euclid.pattern(steps, beats, rotation + i * spread)`:

```ts
const rhythm = Euclid(ac, {
  clock,
  subdivision: 4,
  ...EuclidRhythm.Samba,
  spread: 2,
});
KickDrum(ac, { trigger: rhythm }); // x..x.x.x..x.x.x.  rotation 0 — the samba necklace
TomDrum(ac, { trigger: rhythm.b }); // x.x..x.x.x..x.x.  rotation 2 — the samba as played
CongaDrum(ac, { trigger: rhythm.c }); // x.x.x..x.x.x..x.  rotation 4
ClaveDrum(ac, { trigger: rhythm.d }); // x.x.x.x..x.x.x..  rotation 6 — a clapping pattern from Ghana
```

Three of those four are rhythms Toussaint names, off one setting. It is the
same array read at four offsets, so nothing rebuilds and nothing can drift.

`spread: 0` is unison and is the default, so nothing that does not set it plays
differently. `spread` equal to `steps` is unison again.

**No single `spread` reaches all three of E(9,16)'s published entry points** —
they are rotations 5, 10 and 14, spaced 5 and 4, and `spread` gives evenly
spaced entry points. A tradition's are not evenly spaced. It is the same
finding as "there is no canonical origin", one level up.

At `steps: 16, beats: 5, spread: 4` the four channels **tile the cycle**: every
step filled, none struck by more than two voices, no unison downbeat. That is
hocket, and it is a different texture from four independent generators:

| design                                  | silent |  1 hit |     2 |     3 |     4 |
| --------------------------------------- | -----: | -----: | ----: | ----: | ----: |
| independent `beats` 4/5/7/9, rotation 0 |      1 |      8 |     5 |     1 |     1 |
| **one pattern, `E(5,16)`, `spread: 4`** |  **0** | **12** | **4** | **0** | **0** |

**Tiling is a property of that setting, not of `spread`.** On the same
`E(5,16)`, `spread: 3` leaves eight of sixteen steps silent and strikes two of
them with all four voices — worse than the row above it. Four of the sixteen
spreads tile; one is unison. The fan is not layering, either: onsets move
rather than accumulate.

The rotations of the rhythms Toussaint publishes as played variants — the ones
`spread` walks between — are in the
[package README](https://github.com/danigb/synthlet/tree/main/packages/euclid#the-rhythm-as-played).

## Parameters

### Pattern

- `steps`: the number of steps in the sequence. Default `8`. `0` is legal and
  means silence — a pattern with no steps has nothing to play.
- `beats`: the number of beats in the sequence. Default `3`, so `steps` and
  `beats` together default to the tresillo, `E(3, 8)`: `Euclid(ac, { clock })`
  with nothing else patched plays a rhythm. `0` is legal and means silence, the
  same way `steps: 0` does — a rhythm with no beats has nothing to play.
  `beats` at or above `steps` is every step.
- `rotation`: the rotation of the sequence. Default `0`. The generated pattern is
  Bjorklund's rhythm up to rotation, and a necklace has no canonical starting
  point — this is how you choose one, counted in steps. It declares a minimum of
  `0`, so the node **clamps** a negative value where `Euclid.pattern(8, 3, -2)`
  **wraps** to `rotation: 6`. Both are deliberate: a parameter has a declared
  range and a pure function does not. Above `steps`, both reduce modulo `steps`.

- `spread`: how far apart the fan's four channels are, in steps. It is in
  `rotation`'s own units and carries `rotation`'s range. `0` is unison and is
  the default. It rebuilds nothing — the fan is an offset applied when the
  pattern is read, not a second pattern — so it is the one count that does not
  go through the pattern cache.

All four are counts and all four are floored — they arrive from an
`AudioParam` as floats, and half a step is not a step.

The generator is
[Morrill's construction](https://arxiv.org/abs/2206.12421) (2022, §4), one
integer comparison per step; the package README has the derivation and what it
is checked against.

### Clock

- `clock`: a clock that drives the rhythm. This is the clock's **phase ramp** -
  the `Clock` node itself, not `clock.gate` - because subdividing a clock means
  multiplying its phase. The scaled ramp is read modulo 1, so a value of exactly
  1 is the same phase as 0.
- `subdivision`: how many pattern cycles fit in one clock cycle — a multiplier
  on the incoming phase. Default `1`, maximum `20`.
- `swing`: the long-short ratio of each pair of steps. Default `1`, straight;
  `2` is triplet feel, `3` — the maximum — is dotted-eighth. It moves one
  boundary inside each pair rather than delaying the odd steps, so the gate
  stays the same fraction of whichever step it is in and `swing: 1` is
  bit-identical to no swing at all. Swing is applied against the
  **subdivision**, so `subdivision: 4` swings sixteenth pairs and
  `subdivision: 2` eighth pairs; at `subdivision: 1` there is nothing to
  subdivide and it is inert. At an odd `subdivision` the leftover step is a
  straight, full-length one, so a clock cycle always holds exactly
  `subdivision` steps.

  This is the MPC/DAW convention rather than a model of jazz swing.
  [Honing & de Haas (2008)](https://doi.org/10.1525/mp.2008.25.5.471) test the
  constant-ratio-at-any-tempo model every DAW implements and reject it — real
  swing ratios are "systematically adapted to a global tempo", plateau near
  2.2:1 at slower tempi, and need "a more complex model". The knob is the
  convention users expect and can turn; it is not a claim about how anybody
  plays.

### Output

- `pulseWidth`: how much of each step a hit is high for, as a fraction of the
  step. Default is `0.5`. `1` means the widest hit that still retriggers, not
  100% — a hit that never falls can never fire anything again.
- `reset`: on a rising edge, the next step boundary is step 0 of the pattern.
  Edge triggered, and `a-rate` so it lands on its own sample.

`pulseWidth` and `reset` apply to **every output**: there is one width, one
clamp and one step counter behind the hits, the rests and the fan alike.

Two `Euclid`s on one `Clock` each keep a private step counter starting from
whenever that node was built, so they play different rotations of the same
pattern unless you align them. Patch both `reset` inlets from the same gate and
they agree.

Two swung `Euclid`s on one `Clock` always swing the **same way** — which half of
a pair a sample falls in is a function of the clock phase alone. What `reset`
does is put their patterns on the same half of the pair.

Euclid's output is a [gate](/docs/gates-and-triggers): each hit is a pulse over
the first `pulseWidth` of its step, so two adjacent hits are two triggers. (It
used to hold the step's level until the next step, which merged them - a `4/4`
pattern fired exactly once.)

## Recipes

### Two patterns that start together

Each `Euclid` keeps a private step counter that starts whenever _that node_ was
built, so two of them on one clock play different rotations of the same pattern
unless you say otherwise. Measured across 32 birth offsets, 28 diverge. Patch
both `reset` inlets from one gate and they agree:

```ts
const clock = Clock(ac, { bpm: 120, beatsPerBar: 4 });
const a = Euclid(ac, {
  clock,
  ...EuclidRhythm.Tresillo,
  reset: clock.downbeat,
});
const b = Euclid(ac, {
  clock,
  ...EuclidRhythm.BossaNova,
  reset: clock.downbeat,
});
```

`clock.downbeat` is one choice; any gate will do. There is no transport and no
global timeline — this is the mechanism.

### A kick and a hat off one node

`rhythm` is the hits and `rhythm.rests` is the steps they leave empty. Sparse
kick, busy hat, and they cannot skew, because they are one step read twice:

```ts
const rhythm = Euclid(ac, { clock, ...EuclidRhythm.Tresillo });
KickDrum(ac, { trigger: rhythm }); // x . . x . . x .
HiHatDrum(ac, { trigger: rhythm.rests }); // . x x . x x . x
```

### The fan on four drums

The demo above, written out. One pattern, four entry points, four voices:

```ts
const rhythm = Euclid(ac, {
  clock,
  subdivision: 4,
  ...EuclidRhythm.Samba,
  spread: 2,
});
KickDrum(ac, { trigger: rhythm }); // rotation 0 — the samba necklace
TomDrum(ac, { trigger: rhythm.b }); // rotation 2 — the samba as played
CongaDrum(ac, { trigger: rhythm.c }); // rotation 4
ClaveDrum(ac, { trigger: rhythm.d }); // rotation 6 — a clapping pattern from Ghana
```

Three of the four are rhythms Toussaint names, off one setting.

### Subdividing

`subdivision` multiplies the incoming phase, so it divides the clock's cycle into
that many steps. Feed the beat phase for sixteenths, the bar phase for a figure
that spans the whole bar:

```ts
Euclid(ac, { clock, subdivision: 4, ...EuclidRhythm.BossaNova }); // 16 steps a beat
Euclid(ac, { clock: clock.bar, subdivision: 8, ...EuclidRhythm.Tresillo });
```

`Euclid` has no tempo of its own; see [Clock](/docs/clock) for where the timing
comes from.
