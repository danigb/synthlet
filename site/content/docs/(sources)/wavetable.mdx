`@synthlet/wavetable-oscillator`

This module implements a wavetable oscillator with morphing compatible
with [WaveEdit Online](https://waveeditonline.com/) wavetable format.

```ts
import {
  WavetableOscillator,
  registerWavetableOscillatorWorklet,
  loadWavetable,
} from "@synthlet/wavetable-oscillator";

// Register the worklet
const audioContext = new AudioContext();
await registerWavetableOscillatorWorklet(audioContext);

// Create the oscillator and connect it to the destination
const osc = WavetableOscillator(audioContext, {
  morph: 0.5,
});
osc.connect(audioContext.destination);

// Load a wavetable
const wavetable = await loadWavetable("SYNLP10");
osc.setWavetable(wavetable);

// Change the frequency
osc.frequency.value = 880;
```

## Parameters

- `frequency`: The frequency of the oscillator in Hz. Default is 440. a-rate and
  **bipolar**, `-20000` to `20000`: an oscillator connected here is linear FM,
  and the negative half runs the read pointer backwards rather than half-wave
  rectifying the modulator, which is through-zero FM.
- `detune`: Detune in cents, `-1200` to `1200`. Default is 0, a-rate.
- `morph`: The wavetable position, 0 (first plane) to 1 (last plane). Default is 0. a-rate, so an `Lfo` connected to it scans the table at any rate and any
  shape; a position that jumps is ramped over 64 samples rather than clicked.
- `sync`: Hard sync. A rising edge restarts the table read at `phase`. `0` to
  `1`, default 0, and **a-rate**, unlike every other gate in the library: the
  reset is placed at the sub-sample instant the gate crossed zero, which a
  k-rate gate could only round to the nearest render quantum.
- `segments`, `pitchChaos`, `pitchSpread`, `ampChaos`, `ampSpread`: the
  stochastic mode, below. Both spreads default to 0 and that is an exact
  bypass.

`phase` is a **construction option** rather than a parameter - `number` or
`"random"` - because it is a one-time initial condition. Three instances built
at the default phase 0 begin phase-locked and comb through their attack;
`phase: "random"` is what stops them:

```ts
const stack = [-7, 0, 7].map((detune) =>
  WavetableOscillator(audioContext, {
    frequency: 220,
    detune,
    phase: "random",
  }),
);
```

## Hard sync

Patch an oscillator into `sync` and its rising edges restart the table read.
The note's pitch becomes the master's; sweeping the slave moves a formant
through it, which is the sound hard sync exists for and something
`OscillatorNode` cannot make at all.

```ts
const master = PolyblepOscillator(audioContext, { frequency: 110 });
const slave = WavetableOscillator(audioContext, {
  frequency: 275,
  sync: master,
});
```

The restart is a step **and** a corner in the output, and both are band-limited
with the same 4-point B-spline kernels `@synthlet/polyblep-oscillator` uses —
worth 17.6 to 33.9 dB of alias rejection over a plain phase-to-zero reset. It is
also why this node has **two samples of latency** (45 µs at 44.1 kHz, the same
as `@synthlet/polyblep-oscillator`): a correction is written backwards into
samples that have been computed but not yet emitted.

## Stochastic mode

Raphael Radna's _Dynamic Stochastic Wavetable Synthesis_ (DAFx-23), layered over
whichever table is loaded. The table is split into `segments` equal parts, and
each part gets a pitch deviation and an amplitude deviation drawn by a bounded
random walk that iterates once per wave cycle. The pitch deviation bends the read
rate; the amplitude deviation is added to the sample, interpolated across segment
boundaries so none of them is a step, and folded at ±1. The range is drift →
thickening → granular roughness → noise.

```ts
// organic drift: every note slightly different, nothing else changes
const osc = WavetableOscillator(audioContext, {
  pitchSpread: 0.2,
  pitchChaos: 0.3,
});
```

`pitchSpread` (0–24 semitones) and `ampSpread` (0–1) are the barriers — how far a
deviation can get from centre — and each one at 0 switches its path off entirely.
`pitchChaos` and `ampChaos` (0–1) are the step sizes, as a fraction of the
barrier: how much of that range the walk may cross in one cycle. `segments`
(0–256, k-rate) is the roughness and the brightness.

The four a-rate parameters are **read once per wave cycle**, because that is the
rate the walk runs at. An envelope into `ampSpread` makes the roughness part of a
note's shape; an audio-rate source there does not give audio-rate modulation.

**This stage is not band-limited, and the paper says so.** The knees the
deviations put at the segment boundaries are a broadband source that no amount of
table band-limiting removes, so the spreads and `segments` are
roughness-versus-aliasing knobs rather than tone controls — see the package
README for the measured numbers. `{ pitchPerSegment: true }` at construction is
the rougher, more aliased pitch mode; the default draws one pitch deviation per
cycle, which is the one antialiasing measure the paper implements.

## Loading wavetables

This package provides a couple of helper functions to list available wavetables and load them:

```ts
import {
  loadWavetable,
  fetchWavetableNames,
} from "@synthlet/wavetable-oscillator";

const wavetableNames = await fetchWavetableNames(); // => ["SYNLP10", "SYNLP165",   ...]

const wavetable = await loadWavetable("SYNLP10");

osc.setWavetable(wavetable);
```

Wavetables are stored at [smpldsnds wavedit repository](https://github.com/smpldsnds/wavedit-online). The list of available tables is [here](https://smpldsnds.github.io/wavedit-online/samples/files.json)
