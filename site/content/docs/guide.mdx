This guide will show you how to use the Synthlet modules.

## Create

To create a module, you need to call the `Module` function that will return an instance of an [AudioWorkletNode](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletNode).

The create function will take two arguments, the `audioContext` and an object with optional configuration and initial values of each parameter:

```js
const osc = PolyblepOscillator(audioContext, {
  frequency: 440,
});

const env = AdsrEnv(audioContext, {
  attack: 0.1,
  decay: 0.1,
  sustain: 0.5,
  release: 0.1,
});
```

## Connect modules to the audio graph

Since returning nodes are normal [AudioWorkletNodes](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorkletNode/AudioWorkletNode) , you can [connect](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect) them to the audio graph as you would with any other node:

```js
// Connect a module to another
osc.connect(audioContext.destination);

// Connect a module to a parameter (modulation)
adsr.connect(osc.frequency);
```

## Parameters

Each module has a set of parameters exposed as [AudioParam](https://developer.mozilla.org/en-US/docs/Web/API/AudioParam) that you can control using the `value` property the same way as you would with any other Web Audio API node:

```js
osc.frequency.value = 880;
adsr.attack.value = 10;
adsr.attack.setValueAtTime(0.1, audioContext.currentTime + 5);
```

## Connect parameters on constructor

Unlike WebAudioAPI, Synthlet create functions accepts other modules as parameters. This is useful to connect modules on creation:

```js
const lfo = Lfo(audioContext, { type: LfoType.ExpRampUp });
const amp = Gain(audioContext, { gain: lfo });
```

The lfo is now connected and modulating the gain of the amp node.

## Start and stop

There are no `start` and `stop` methods in Synthlet modules, sources are started by default.

<Callout title="No start/stop" type="warn">
  Unlike the standard WebAudio API, Synthlet modules starts automatically.
</Callout>

The modules that needs some kind of start/stop (envelopes, sequencers, etc...) the control is managed with parameters too. For example, `start` and `stop` methods are normally replaced by a `gate` parameter that you can control using the `setValueAtTime` method:

```js
adsr.gate.value = 1; // equivalent to start()
adsr.gate.value = 0; // equivalent to stop()
```

The advantage is that you can use a module to start/stop other modules. Everything can be connected.

## Connect and disconnect

Synthlet modules use the same [connect](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/connect) and [disconnect](https://developer.mozilla.org/en-US/docs/Web/API/AudioNode/disconnect) methods as any other AudioNode:

```js
adsr.connect(osc.frequency);
adsr.disconnect();
adsr.connect(amplitude.gain);
```

<Callout title="Disconnect is not enough" type="warn">
  Audio worklets still running even if you disconnect them from the audio graph.
  If you want to fully stop them you have to `dispose`.
</Callout>

## Dispose

Dispose is a handy function that fully disconnects and stop the module:

```js
osc.dispose();
```

It also disconnects all dependencies:

```js
const gate = Param(audioContext);
const adsr = AdsrEnv(audioContext, { gate });
const osc = PolyblepOscillator(audioContext, { frequency: adsr });

...
osc.dispose(); // disposes adsr, and the gate Param with it
```

Unlike the `connect` in standard WebAudio API, `dispose` can be called more than once (but only the first call will have effect) and once called, the module is not usable anymore.

## Composing modules

A group of modules wired together is itself a module: it has an output you can
`connect()`, parameters you can automate, and a `dispose()` that tears the whole
thing down. There is no special API for building one - three rules:

1. **Wire with `connect()`.** It chains, and a mix is two `connect()` calls into
   the same node.
2. **End in a `Gain`.** The compound then has a predictable type, an input
   anything can connect to, and a `volume` for free.
3. **Declare it with `Compound({ output, owns, exposes })`.** `owns` is what
   `dispose()` tears down: anything you passed to a factory is already owned by
   the module you passed it to, so this is the list of nodes you connected by
   hand. Listing extras is free - `dispose()` runs once per node - so when in
   doubt, list everything you created. `exposes` is the compound's public
   surface: an inlet is a `Param` node's `.input` when it needs scaling (a
   volume in decibels) or fan-out (one gate driving two envelopes), and the
   module's own `AudioParam` otherwise.

```ts
import {
  AdsrAmp,
  AdsrEnv,
  Compound,
  Gain,
  Param,
  PolyblepOscillator,
  Svf,
} from "synthlet";

function Voice(ac: AudioContext, frequency = 440) {
  // Inlets: gate fans out to two envelopes, volume is in decibels.
  // Both need a Param node; anything else can expose its AudioParam directly.
  const gate = Param(ac);
  const volume = Param.db(ac, -12);

  const osc = PolyblepOscillator(ac, { frequency });
  const filterEnv = AdsrEnv(ac, { gate, gain: 3000, offset: 2000 });
  const filter = Svf(ac, { frequency: filterEnv });
  const amp = AdsrAmp(ac, { gate });
  const out = Gain(ac, { gain: volume });

  osc.connect(filter).connect(amp).connect(out);

  return Compound({
    output: out,
    owns: [osc, filterEnv, filter, amp, gate, volume],
    exposes: {
      gate: gate.input,
      volume: volume.input,
      osc,
      filter,
    },
  });
}
```

The result is used like any other module:

```ts
const voice = Voice(ac, 220);
voice.connect(ac.destination);

voice.gate.value = 1;
voice.osc.frequency.value = 330;

voice.dispose(); // every node above, in one call
```

`MonoSynth` and the drums are written exactly this way - read
[mono.ts](https://github.com/danigb/synthlet/blob/main/packages/synthlet/src/synths/mono.ts)
for the same shape at full size.

## Offline rendering

Every factory and every registrar takes a [BaseAudioContext](https://developer.mozilla.org/en-US/docs/Web/API/BaseAudioContext), not an `AudioContext`. Nothing in Synthlet calls `resume`, `suspend` or `baseLatency`, and `audioWorklet` lives on the base type - so an [OfflineAudioContext](https://developer.mozilla.org/en-US/docs/Web/API/OfflineAudioContext) registers and renders the same graph, faster than real time and into a buffer:

```js
import { registerMonoSynth, MonoSynth } from "synthlet";

// 1 mono channel, 2 seconds at 48 kHz
const ctx = new OfflineAudioContext(1, 2 * 48000, 48000);

await registerMonoSynth(ctx);

const synth = MonoSynth(ctx, { frequency: 220 });
synth.connect(ctx.destination);
synth.gate.setValueAtTime(1, 0.1);
synth.gate.setValueAtTime(0, 0.4);

const buffer = await ctx.startRendering();
```

`AudioContext` is a subtype of `BaseAudioContext`, so the live code above is the offline code: nothing changes but the context you pass in.

Rendering offline is how you verify a patch without listening to it. **Two renders of the same graph produce identical samples** - the spec makes an `OfflineAudioContext` deterministic, and Synthlet asserts it in [offline.test.ts](https://github.com/danigb/synthlet/blob/main/packages/synthlet/src/offline.test.ts), which renders a worklet graph and a whole `MonoSynth` under [node-web-audio-api](https://github.com/ircam-ismm/node-web-audio-api) in CI. So a rendered buffer is a reference you can diff against, not just a preview.

Synthlet does not ship a `renderOffline` helper. Constructing the context is the three lines above and it belongs to you, and a WAV encoder is not a synthesis module - if you want that convenience, [smplr's `renderOffline`](https://github.com/danigb/smplr) has it, and it takes any `BaseAudioContext` too.

## Installing individual modules

If you want to optimize for bundle size, you can use the individual module packages and register each module individually.

Install:

```package-install
@synthlet/polyblep-oscillator
```

And use:

```js
import {
  registerPolyblepOscillator,
  PolyblepOscillator,
} from "@synthlet/polyblep-oscillator";

const audioContext = new audioContext();
await registerPolyblepOscillator(audioContext);
const node = PolyblepOscillator(audioContext, { frequency: 440 });
```
