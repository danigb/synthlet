A lookahead brickwall limiter that is designed to be used as last effect before the destination. It ensures the output level is always below the threshold.

It looks ahead by a couple of milliseconds, so it can bring the gain down _before_ a peak arrives rather than reacting after it, and it measures peaks on a 4× oversampled reconstruction — so a signal that never exceeds full scale sample-by-sample, but overshoots between samples, is still caught.

```ts
import { LookaheadLimiter } from "synthlet";

const limiter = LookaheadLimiter(audioContext, {
  threshold: -1,
});

connect(limiter).connect(audioContext.destination);
```

## Parameters

- `threshold`: The true-peak ceiling in dBTP [-24, 0], default -1
- `release`: Recovery time in ms, measured 10-90% [10, 1000], default 168
- `gain`: Input drive in dB, applied _before_ the detector [-12, 24], default 0
- `lookahead`: The lookahead window in ms [0.5, 5], default 2 — a construction option, not an `AudioParam`: it sizes the delay line, so changing it would change the node's latency

`gain` is a drive, not a makeup gain. A makeup gain multiplies the output _after_ the ceiling is enforced, which would destroy the guarantee, so there isn't one — push `gain` up and lower `threshold` instead.

Below the threshold the limiter is a bit-exact passthrough, delayed. Automating `threshold` downward takes `lookahead` samples to reach the smoothed gain, though the arithmetic backstop reads the current value, so the hard bound holds instantly.

## Showing the gain reduction

`meter: true` publishes how hard the limiter is working — the block's largest reduction in dB, `20·log10` of the smallest gain it applied. Off by default, because a limiter sits on every master chain and most have nothing reading this.

```ts
const limiter = LookaheadLimiter(ac, { threshold: -1, meter: true });
limiter.getLevels().gainReduction; // 0 doing nothing, -6 took 6 dB off
limiter.subscribe((levels) => draw(levels.gainReduction));
```

It is the same contract [`@synthlet/level-meter`](/docs/level-meter) publishes, shared by copy between the two packages, so the meter's renderer draws it with no adapter:

```ts
new LevelMeterUI({ mode: "reduction", minDb: -20 }).attach(canvas, limiter);
```

## Latency

The node reports the delay it introduces — the lookahead window plus the detector's 6-sample group delay:

```ts
limiter.latencySamples; // 102 at 48 kHz with the default 2 ms
limiter.latencyTime; // the same, in seconds
```

Web Audio has no automatic delay compensation, so any dry signal mixed in parallel with the limiter must be delayed by this much by hand:

```ts
const dry = new DelayNode(audioContext, { delayTime: limiter.latencyTime });
```

## Checking the ceiling

The limiter's true-peak detector is [the level meter's](/docs/level-meter) — one
implementation, so the two agree about dBTP by construction rather than by
inspection. To see what the limiter is actually delivering, tap its output:

```ts
import { LevelMeter } from "synthlet";

const meter = LevelMeter.tap(limiter, { truePeak: true });
meter.getLevels().truePeak(0); // dBTP, against your threshold
```

[Metering and loudness](/docs/metering-and-loudness) is the guide: which number
to check, the delivery targets, and how to normalise a render before limiting
it.

- [ITU-R BS.1770-4](https://www.itu.int/rec/R-REC-BS.1770), Annex 2 — true-peak measurement. Detection here is BS.1770-_style_ 4× true-peak: the interpolator is a 48-tap Hann-windowed sinc, not the ITU reference coefficients, and its measured accuracy is ±0.1 dB from 60 Hz to 10 kHz at 48 kHz, ±0.35 dB from there to 20 kHz
